# 后端可靠性修复记录

## 已实现

- 调度：缺失依赖补齐；失败阻断下游；异常向调用方传播；同会话重复调度拒绝；结果及检查点事务提交。
- 检查点：`is_stale` 校验，以及源码/Trace/smap/插件实现/插件配置内容指纹；上游重跑使下游失效。
- 隔离：分析和预处理 worker；有限任务队列、超时和 JS 堆预算；worker 完成后释放；重启遗留任务标记失败。
- 存储：events 主键改为 `(session_id,id)`，自动迁移保留现有记录；F4 用预聚合 CTE 代替读写明细的笛卡尔关联，并修正参数绑定。
- Trace：有界缓冲拒绝覆盖；异步写入串行化；显式 flush/close 报告写入失败；SAB 背压失败明确报错；读取校验记录边界、格式版本与截断。
- 导入：gzip 流式解压到唯一临时目录，限制解压大小；finally 清理文件；插件失败回滚到之前提交的结果。
- 身份：v4 携带动态绑定、脚本、调用、上下文和调用配对信息；普通函数、箭头函数和脚本分配词法帧标识，闭包自然捕获对应帧。
- 依赖：使用实际执行的 readVar，而非静态 use-set；保留读改写依赖；await 挂起前提交读写；catch/finally 恢复上下文。
- 分析：污点正向传播截止到下一次写入，反向只找最近定义；A1/A2/F4 匹配动态 binding_id；F3 按调用配对 ID 处理交错返回。
- 插桩：轻量读取限于已初始化的不可变局部绑定；不确定路径使用原生值；可选链保留原生短路。
- 执行：文件名禁止路径；本机监听和 Origin 白名单；最小子进程环境；统一插桩并发、输出与超时限制。
- MCP：污点工具改用 POST 请求及正确字段，支持静态 scope 筛选。
- 测试：纳入 serialize/preprocess/full-pipeline；新增后端、动态绑定、日志可靠性和语义差分回归；CI 运行两组测试。

## 升级和兼容

新输出为 JTB1 v4；新版读取器兼容 v1–v3。旧读取器必须升级后才能读取 v4。
新增钩子的插桩产物必须与新版 runtime 配套；请重新生成运行时 bundle 和插桩产物。
旧检查点无指纹会自动失效。旧数据库中因事件主键冲突已经被丢弃的记录无法通过迁移恢复，需要重新导入原始 Trace。

`trace_integrity` 为 `complete`、`gaps`、`unverified-end` 或 `unknown`。
只有有显式 TRACE_END 且序号连续的轨迹才标为 complete；没有结束标记的旧文件及非显式关闭的收集文件为 unverified-end。
损坏文件导入失败，不把已解析前缀当作成功结果。失败重跑保留之前提交的数据和失败状态。

## 明确保留的边界

- 数据流仍是语句粒度，不是完整表达式级 SSA：同一表达式中复杂的读写顺序、隐式控制依赖和 native 内部计算不能作为精确证明。
- 旧格式缺少动态绑定时，只能退回静态作用域关联；不要把近似结果当作跨调用精确溯源。
- 可选链目前保留操作数钩子，省略属性/调用包装，优先保证短路和副作用语义。
- SQLite 仍是单写者；长插件事务期间读取使用 WAL 快照，其他写请求可能等待或收到 busy。worker 堆预算不等于操作系统总内存配额。
- A2 已实现磁盘分片与有界流式构图，A1 改用按需磁盘索引；分片细节和容量边界见 [Disk-Sharded-Graph.md](Disk-Sharded-Graph.md)。当前不续写中断的半成品分片。
- 子进程不是 OS 沙箱，不提供网络、文件系统权限或恶意代码隔离。多用户托管部署需要另加容器/权限隔离与身份认证。
- 本次没有实现完整 CFG/SSA 优化器和持久化插桩缓存；这些属于后续性能架构工作，不能用修复结果宣称已经具备。

## 验证命令

```sh
npm test
npm test --prefix analyzer
node analyzer/benchmark.mjs 50000
```

基准输出包含处理时间、每秒事件数、API 线程事件循环 p99、定时器推进次数和 worker 堆使用量。
它是合成负载的单机 smoke benchmark，不是生产吞吐承诺，也不用于宣称未经对照的性能提升倍数。

- 根测试：782 项通过；后端测试：16 项通过；`git diff --check` 通过。

- API 主线程事件循环 p99：12.21 ms；分析期间 10 ms 定时器推进 129 次。

- 此基准未施加并发写 API 压力，不能据此推断长事务期间写请求的延迟。

## IR 与沙盒接入前的流程整理

阶段定义与自动编排集中到 `SessionAnalysis.mjs`。进度通知不再触发下一阶段；整个流程由一个 worker 任务覆盖，失败停止后续阶段。
单插件重跑复用批量生命周期；必需依赖与可选分析输入共同驱动检查点失效，移除路由中的手工下游列表。
预处理、插桩、运行与分析共用 `ExecutionBudget.mjs` 的活动/等待预算。`runner.maxConcurrency` 现在表示整体活动上限。
图 generation 增加提交后回收、reader 租约、worker 终止清理和启动恢复，详见分片文档。
新增回归覆盖完整四阶段、源码映射、失败/取消/超时恢复、重复任务、单插件失效、混合执行预算和图快照回收。

这些整理不包含 IR/静态分析实现、jsdom 环境实现，也没有改造插桩器的进程内全局状态。
当前子进程插桩方式继续提供状态隔离；未来需要同进程多个插桩上下文时，再独立改造该模块。
